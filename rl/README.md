# rl — 크리틱 역할로 읽는 알고리즘 여섯, 같은 테트리스 위에서

이 디렉터리는 `RL_공부계획.pdf`의 축 하나를 코드로 옮긴 것이다. 그 축은

> **크리틱이 갱신식의 어디에 들어가는가.**

여기 있는 전략들은 서로 다른 문제를 푸는 서로 다른 알고리즘이 아니다. **같은 테트리스, 같은 8차원 특징, 같은 보상, 같은 망 크기, 같은 옵티마이저** 위에서 그 한 축만 옮겨 간 것이다. 그래야 성능 차이를 알고리즘 탓으로 돌릴 수 있다.

읽는 순서는 공부계획 그림의 번호 그대로다: ① → ② → ③ → ④, 그리고 축 밖의 두 대조군(CEM, 1-ply 탐색).

## 축을 따라가기

### 먼저: 정책 그래디언트 정리가 무엇을 요구하는가

네 알고리즘 모두 정책을 이렇게 고친다.

```
θ ← θ + α · Ψ_t · ∇ln π(A_t | S_t)
```

`∇ln π`는 "이 행동을 더 하게 만드는 방향"이고, **`Ψ_t`가 "얼마나"를 정한다.** 네 알고리즘의 차이는 전부 `Ψ_t`를 무엇으로 놓느냐 하나다. 크리틱이 들어가는 자리가 바로 여기다.

이 프로젝트에서 정책은 **배치(placement) 위의 softmax**다. 행동마다 afterstate 특징 `f(s,a)`가 있고 선호도 `h(s,a) = net(f(s,a))`를 softmax한다 (Sutton 13.2). 그래서

```
∇ln π(a|s) = ∇h(a) − Σ_b π(b) ∇h(b)
```

이고, 이건 역전파 한 번에 끝난다 — 출력 계수를 `onehot(a) − π`로 주면 된다. `nn.py`의 `backward`가 그 계산이다.

---

### ① REINFORCE — 크리틱 없음

```
Ψ_t = G_t          (실제로 받은 할인 리턴)

θ ← θ + α · G_t · ∇ln π(A_t | S_t)
```

**크리틱은 무엇을 하는가: 아무것도 하지 않는다. 없다.**
`v̂`라는 함수 자체가 존재하지 않는다. 갱신의 크기는 에피소드가 끝난 뒤 실제로 세어 본 리턴이 정한다. 편향이 전혀 없다는 것이 장점이고, 그 대가는 분산이다. 리턴 하나에 그 에피소드에서 일어난 모든 우연 — 어떤 조각이 나왔는지, 언제 죽었는지 — 이 통째로 섞여 들어오고, 그 잡음이 곱해진 채로 파라미터에 들어간다. 게다가 `G_t`는 끝까지 가 봐야 알 수 있으므로 **에피소드가 끝나기 전에는 한 발짝도 배울 수 없다.**

---

### ② REINFORCE + baseline — 크리틱은 있는데, 판단은 안 한다

```
Ψ_t = G_t − v̂(S_t)

θ ← θ + α ( G_t − v̂(S_t) ) ∇ln π(A_t | S_t)
w ← w + α_w ( G_t − v̂(S_t) ) ∇v̂(S_t)
```

**크리틱은 무엇을 하는가: 분산만 깎는다. 갱신이 가리키는 방향에는 손대지 않는다.**

행동에 의존하지 않는 어떤 `b(s)`에 대해서도

```
Σ_a b(s) ∇π(a|s) = b(s) ∇ Σ_a π(a|s) = b(s) ∇1 = 0
```

확률의 합은 언제나 1이고 상수의 기울기는 0이다. 그래서 **빼는 값이 무엇이든 기댓값에는 흔적이 남지 않는다.** `v̂`가 엉터리여도 갱신 방향은 평균적으로 옳다.

이것이 Sutton이 ②를 액터-크리틱이라 부르지 않는 이유다. `v̂`는 "이 상태는 원래 이 정도 값이니 그만큼 빼고 보자"고 눈금을 옮겨 줄 뿐, 어느 행동이 좋았는지 **판정하지 않는다.** 크리틱이라 불릴 자격이 없다.

실용적으로는 큰 차이를 만든다. `G_t` 대신 `G_t − v̂`를 쓰면 "평균보다 나았나"만 남으므로 곱해지는 수의 크기가 줄고, 학습이 훨씬 안정된다. 아래 결과표에서 ②가 ①보다 확실히 나은 것이 그 효과다.

---

### ③ A2C (1-step) — 크리틱이 표적 안으로 들어간다

```
Ψ_t = R_{t+1} + γ v̂(S_{t+1}) − v̂(S_t)

θ ← θ + α ( R_{t+1} + γ v̂(S_{t+1}) − v̂(S_t) ) ∇ln π(A_t | S_t)
w ← w + α_w ( R_{t+1} + γ v̂(S_{t+1}) − v̂(S_t) ) ∇v̂(S_t)
```

**②와 다른 곳은 한 군데다. `G_t`가 `R_{t+1} + γ v̂(S_{t+1})`로 바뀌었다.**

`pg.py`에서 이 한 줄을 `THE ONE LINE`으로 찾을 수 있다. 코드도 정말 한 줄이다.

```python
target = (r + GAMMA * v_next) if mode == "a2c" else G
delta  = target - v
```

**크리틱은 무엇을 하는가: 값을 매긴다. 표적 자체를 정한다.**

`v̂(S_{t+1})`은 지금 갱신하는 상태가 아니라 **다음 상태의 추정값**이다. 이게 표적 안으로 들어가면 성질이 뒤집힌다. `v̂`가 틀린 만큼 표적이 틀리고, 표적이 틀리면 갱신 방향 자체가 틀린다. **편향이 생긴다.** ②에서는 `v̂`가 아무리 엉터리여도 방향이 안 변했는데, ③에서는 변한다. 이제 크리틱이 실제로 판단에 끼어든다.

대가로 얻는 것: **에피소드가 끝나기를 기다릴 필요가 없다.** `R + γv̂(S')`는 한 스텝만 밟으면 계산된다. 온라인으로, 매 스텝 배운다.

> **한 문장 요약 — 크리틱의 유무가 아니라 부트스트랩 참여 여부가 분류를 가른다.** ②는 `v̂`를 갖고도 정책 기반이고, ③부터 액터-크리틱이다.

---

### ④ DQN (afterstate) — 액터가 사라진다

```
y = r + γ max_{a'} Q(s', a')          ← 여기에 행동 정책이 없다
L = ( Q(s,a) − y )²
π(s) = argmax_a Q(s, a)
```

**크리틱은 무엇을 하는가: 크리틱이 곧 정책이다.**

액터가 없어진 게 아니라 **파라미터가 0개인 액터**가 된 것이다. `argmax_a Q`가 액터다. 크리틱이 정해지는 순간 정책이 딸려 나온다. ③에서 `π(a|s)`를 지우고 `a = argmax_a Q`로 대체한 것이 ④다.

그런데 이 종속에는 대가가 있고, 그 대가가 **on/off-policy의 정체**다. 위 표적을 다시 보면 **행동 정책이 어디에도 나오지 않는다.** `(s,a,r,s')`는 환경이 준 표본이고 `max`는 누가 그 행동을 골랐는지 상관하지 않는다. 그래서 **낡은 정책이 만든 데이터도 여전히 유효하다** — 리플레이 버퍼가 성립하는 근거가 이 한 줄이다.

정책 그래디언트는 반대다. `∇J ∝ Σ_s μ_π(s) Σ_a q_π(s,a) ∇π(a|s)`에서 상태분포 `μ_π`도 `q_π`도 **지금 정책**에 딸려 있다. 옛 표본은 그냥 틀린 표본이다. **on/off-policy는 설계자의 취향이 아니라 식에서 강제되는 성질이다.**

**afterstate가 여기서 왜 편한가.** 보통 DQN은 행동마다 출력 헤드가 필요하고 행동 집합이 고정이어야 한다. 테트리스는 둘 다 아니다 — 합법 배치 수가 조각마다 변한다. 그런데 배치에서 결과 보드로 가는 전이가 **결정적이고 이미 알려져 있으므로**

```
Q(s,a) = r(s,a) + γ V(afterstate(s,a))
```

스칼라 망 `V` 하나면 충분하고, `max_{a'}`는 **다음 조각의 배치를 열거하는 루프**로 자연히 풀린다. 탐욕 정책이 어차피 돌리던 그 루프다.

**안정화 장치 둘, 그리고 그게 왜 필요한가.**
- **리플레이 버퍼** — 연속한 전이의 상관을 끊고 데이터를 재사용한다. 표적이 off-policy라서 정당하다.
- **타깃 네트워크** — 표적을 얼려 둔 사본으로 계산한다. 없으면 망이 움직이는 순간 표적도 같이 움직여 회귀가 자기 꼬리를 쫓는다. 공부계획 3주차에서 DDPG를 두고 말한 "크리틱의 오차가 곧 정책의 오차가 된다"와 같은 고장이고, 타깃 네트워크가 그에 대한 가장 싼 처방이다.

### 축 밖 ⑴ — CEM 선형 (대조군)

크리틱 없음, 경사 없음, 시간차 없음. 게임 전체를 "가중치 8개를 넣으면 줄 수 하나가 나오는 블랙박스"로 보고 **가중치 공간을 직접 탐색한다.**

가우시안 `N(μ, diag(σ²))`에서 후보를 뽑아 → 각각 여러 게임 돌려 → 상위 elite의 평균/분산으로 갱신 → 노이즈를 조금씩 줄인다. elite 분산에 추가 노이즈 `Z_t`를 더하는 것이 핵심이다(Szita & Lőrincz 2006). 없으면 몇 세대 만에 분산이 붕괴해 그냥 멈춘다.

`argmax`는 `w`의 양수배에 불변이므로 실제 자유도는 7이다. 매 갱신 후 `‖w‖ = 1`로 정규화해 `σ`의 의미를 유지한다.

**이 대조군이 아프게 하는 지점**: 아래 결과에서 CEM이 크리틱 기반 네 개를 압도적으로 이긴다. 정직하게 읽으면 이렇다 — **정책이 숫자 8개뿐이고 롤아웃이 싸면, 공부계획이 다루는 크레딧 할당 기계장치는 값을 못 한다.** 크리틱은 정책이 크고 표본이 비쌀 때 값을 한다. 여기는 둘 다 아니다. 이건 공부계획 "밥약 전 자기 점검" 2번(표본을 얼마나 싸게 뽑을 수 있나)과 4번(내 문제에서 "크리틱이 좋다"가 구체적으로 무엇인가)의 실물 답이다.

### 축 밖 ⑵ — 1-ply 탐색 + 학습된 가치 (4주차 AlphaZero 절)

```
score(p₁) = w·f(afterstate(p₁)) + max_{p₂} w·f(afterstate(p₁ → p₂))
```

가중치는 `cem_linear.json`을 **그대로** 쓴다. 재학습 없음. 달라진 것은 현재 조각과 next 조각을 함께 펼쳐서 평가한다는 것뿐이다.

**크리틱은 무엇을 하는가: 정책을 만들지도, 미분당하지도 않는다. 말단만 평가한다.**
정책 개선을 하는 것은 **탐색**이다. 앞의 여섯과 층이 다른 지점이 여기다 — 정책 개선 연산자가 신경망 바깥에 있다. AlphaZero의 구조적 주장만 남기고 MCTS·정책 헤드·자기대국은 걷어낸 최소 형태다.

**세 지표를 왜 다 싣는가**
- **평균 줄** — 2·3·8번에서 **포화됐다.** 상한에 걸린 게임은 끝난 게임이 아니라서 그 숫자는 실력이 아니라 **내가 건 상한이 정한 하한**이다. 조각을 20만 개(배치 80만 회)까지 올려도 셋은 여전히 안 죽는다(`weights/eval_deep_survival.json`). **셋의 순위를 이 열로 매기면 안 된다.**
- **조각당 점수(원시)** — level 배수(=1+줄수/10)가 게임 내내 오르며 모든 삭제에 곱해지므로 **생존을 다시 재는 셈이다.** 오래 산 2·3·8번이 자동으로 유리해진다.
- **정규화 점수** = `평균(score_delta / level)`. level 배수를 걷어내 **테트리스가 초반이든 후반이든 같은 값**이 되게 한 것. 9번이 학습한 목표가 이것이고, **9번이 전 전략 중 1위다.**

## (A) 우물 특징 — 답: **표현력 문제였다**

#9(점수 목표)가 합격선을 못 넘은 이유가 **표현력**인지 **크레딧 할당**인지를 가르는 시험이다. 같은 55분 예산, 같은 `sigma_min`, 같은 목표(점수). **특징 집합 하나만 다르다.**

추가한 두 특징 (`FEATURE_SETS["wells10"]`):
- **`max_well_depth`** — 가장 깊은 우물의 깊이. 우물 정의는 `cumulative_wells`와 동일. 테트리스는 깊이 4가 필요하므로 **3과 4의 차이가 "기다린다"와 "터뜨린다"의 차이**인데, `cumulative_wells`는 보드가 그 선의 어느 쪽인지 말하지 못한다
- **`well_count`** — **깊이 3 이상** 우물의 개수. 1칸 홈까지 세면 `bumpiness`의 재측정이 된다. 깊이 3부터가 유지하기로 한 약속이고, 둘 있으면 실제 비용이다

| 3,000조각까지 안 죽은 판 | 0/10 | 6/10 | — |
| **50,000조각까지 안 죽은 판** | **0/10** | **0/10** | — |

한 판 운이 아니다 — 10종의 tetris 게임별 **중앙값 57.5%, 최소 47.9%**, 최대 71.5%. **10판 전부가 8종의 최대값(46.5%) 근처이거나 그 위다.**

### ⚠️ 생존은 개선되지 않았다 — 앞서 개선됐다고 쓴 것을 정정한다

처음에 **"점수만 오른 게 아니라 생존도 같이 올랐다"**(8종 0/10 대 10종 6/10)고 적었다. **그건 조각 상한 3,000 안에서만 참이었다.** 상한을 50,000으로 올려 다시 재니 **둘 다 10판 전부 죽는다.**

```
사망 조각 수 (상한 50,000, 홀드아웃 10시드)
8종   [2024, 2042, 2403, 2423, 2561, 3769, 4252, 4398, 4615, 11703]   중앙값 3,165
10종  [ 415,  738, 1259, 1867, 3258, 3451, 4391, 4587, 7490, 9517]    중앙값 3,354
```
**사망 시점이 사실상 같다.** 우물 특징은 **점수와 tetris 비율을 크게 올렸지만 생존은 개선하지 못했다.**

**왜 6/10 으로 보였나 — 상한이 사망 분포의 중앙값 위에 놓여 있었다:**

| 조각 상한 | 8종 도달 | 10종 도달 |
|---:|---:|---:|
| 1,000 | 10/10 | 8/10 |
| 2,000 | 10/10 | 6/10 |
| **3,000** | **5/10** | **6/10** ← 쓰던 상한 |
| 5,000 | 1/10 | 2/10 |
| 10,000 | 1/10 | 0/10 |
| 50,000 | **0/10** | **0/10** |

상한 3,000이 사망 중앙값(3,165 / 3,354) **바로 위**였다. 하필 그 자리라 **생존이 동전 던지기처럼 보였는데 조금만 더 가면 전부 죽는다.** 상한을 어디 두느냐로 "6/10"과 "0/10"이 다 나온다.

> **상한을 명시하지 않은 생존 주장은 주장이 아니다.** 그리고 "충분히 큰 상한"의 기준은 **측정 대상의 사망 분포보다 충분히 위**여야 한다 — 3,000은 그 기준을 만족하지 못했다. 줄 수 포화에서 배운 것과 같은 형태인데, 이번엔 주 지표에서 밟았다.

### 학습된 가중치가 전략을 그대로 쓴다

```
max_well_depth     +0.5748   ← 두 번째로 큰 항. 깊은 우물을 적극 보상
well_count         -0.3503   ← 우물 개수는 벌한다
column_transitions -0.7032
cumulative_wells   -0.0484   ← 8종 대비 우물 총량 페널티가 거의 사라졌다
aggregate_height   +0.0356   ← 높이를 보상한다
```

**`max_well_depth` 양수 + `well_count` 음수 = "깊은 우물을 정확히 하나 유지해라".** `well_count`의 docstring에 "테트리스 전략은 이 값이 정확히 1이길 원한다"고 의도를 적어 뒀는데, **학습이 그 부호를 스스로 찾았다.** 아무도 지정하지 않았다.

### 왜 8종으로는 안 됐나

`cumulative_wells`는 우물의 **비용**을 삼각수로 잰다. 그 하나로는 **"깊은 우물 하나(자산)"와 "얕은 홈 여럿(부채)"을 구분할 수 없다** — 같은 총량을 낼 수 있기 때문이다. 우물을 **관리 대상**으로 다루려면 깊이와 개수를 따로 볼 수 있어야 하는데 8종에는 그 항이 없었다.

> **선형 정책이 표현할 수 없는 전략은 탐색을 아무리 오래 돌려도 찾지 못한다.** #9가 실패한 것은 CEM이 못 찾아서가 아니라 찾을 수 있는 공간에 답이 없어서였다.

### 합격선은 여전히 미달 — 1/3

```
죽지 않는다 (10/10)         0/10     미달   (상한 50,000 기준. 3,000 에서는 6/10 으로 보였다)
tetris 비율 >= 30%         59.2%    달성   (목표치 60% 에 0.8%p 차이)
조각당 점수 cem_linear 2배   1.68x    미달   (8종은 1.27x)
```
**기준은 학습 전에 고정했고 결과를 보고 바꾸지 않는다. 실패로 기록한다.** 다만 세 지표 전부 대조군보다 개선됐고 둘은 문턱에 근접했다.

### 이 비교에 교란이 없다는 근거

```
generations_run: 680      collapsed_at_generation: None      selected: distribution_mean
```
**680세대 전부 실효다**(`sigma_min`이 붕괴를 막았다). 두 실행 모두 같은 예산·같은 `sigma_min`이고, 실험군은 분포 붕괴가 없었으며, 가중치는 선택 잡음에 강한 `distribution_mean`으로 뽑혔다. **예산 교란도, 붕괴 교란도, 선택 잡음도 없다.**

## ①②③④ — 시드 200개 재평가 (이쪽이 결론이다)

시드 10개로는 이 넷을 가를 수 없다. 학습은 그대로 두고 **평가만 시드 200개**(`910,000..910,199`, 전부 미사용)로 늘렸다. 중앙값의 95% 신뢰구간은 부트스트랩 4,000회.

| 알고리즘 | 중앙값 | 95% CI | 평균 | 평균/중앙값 |
|---|---:|---:|---:|---:|
| ① REINFORCE | 76.5 | [70.0, 88.5] | 89.0 | 1.16 |
| ② REINFORCE + baseline | **90.0** | [84.0, 97.5] | 100.1 | 1.11 |
| ③ A2C (1-step) | 65.0 | [60.0, 69.5] | 70.0 | 1.08 |
| ④ DQN (afterstate) | 101.5 | [82.0, 124.0] | 172.5 | **1.70** |

**인접 순위쌍 (중앙값 차의 짝지은 부트스트랩 95% CI, 0을 안 포함하면 갈린 것):**

| 비교 | 중앙값 차 | 95% CI | 판정 |
|---|---:|---:|---|
| ④ DQN − ② baseline | +11.5 | [−11.0, +35.0] | **안 갈린다** |
| ② baseline − ① REINFORCE | +13.5 | [+1.0, +23.5] | **갈린다 — 기준선이 실제로 돕는다** |
| ① REINFORCE − ③ A2C | +11.5 | [+4.0, +24.0] | **갈린다 — ③이 꼴찌다** |

**②와 ③은 인접하지 않지만**, checker가 독립 시드(`660000..660199`)·독립 구현(`web/policies.js`를 node로)으로 잰 값이 **+29.0, CI [+23.0, +40.0], 짝지은 승수 146/200**이다. 내 +25.0이 그 CI 안에 들어온다 — **두 독립 평가가 일치한다.**

> **짝지은(paired) 부트스트랩을 써야 한다.** 전 전략이 같은 시드를 쓰므로 시드별 난이도를 짝으로 상쇄할 수 있고, 그러면 검정력이 크게 오른다. 짝짓지 않은 부트스트랩으로는 ①−②가 [−24.0, +0.0]으로 안 갈렸는데, 짝지으면 [+1.0, +23.5]로 갈린다. **같은 데이터에서 통계 방법만 바꿔 결론이 바뀐 것이다.**

### 읽을 수 있는 것

**1. ③ A2C가 정책경사 세 개 중 꼴찌다. 그리고 이건 통계적으로 확실하다.** ②보다 25줄, ①보다 11.5줄 낮고 두 CI 모두 0을 포함하지 않는다.

이것이 이 프로젝트에서 공부계획의 축과 가장 직접 맞닿는 결과다. ③은 ②에서 `G_t`를 `R + γv̂(S_{t+1})`로 바꾼 것뿐인데, **그 한 줄이 성능을 깎았다.** 부트스트랩이 공짜가 아니라는 것 — 기준선은 분산만 줄이고 편향을 안 넣지만 부트스트랩 표적은 **편향을 넣는다**는 이론이 여기서 값으로 나타났다. 크리틱 `v̂`가 충분히 좋지 않으면 그 오차가 표적에 실려 갱신 방향 자체를 틀리게 만들고, 그 손해가 온라인 학습으로 얻는 이득을 넘어선다.

> **부트스트랩은 크리틱이 좋을 때만 이득이다.** 10분 학습으로 얻은 `v̂`는 그 문턱을 못 넘었다.

**2. ①<②도 갈린다 — 기준선은 실제로 돕는다** (+13.5, CI [+1.0, +23.5]). 즉 **①→②→③이 이론 그대로다**: 기준선을 넣으면 분산이 줄어 좋아지고(①→②), 거기서 부트스트랩으로 한 걸음 더 가면 편향 때문에 나빠진다(②→③).

이 결론은 **두 번 뒤집혔다.** n=10에서 "이론대로"라고 썼다가, 짝짓지 않은 부트스트랩에서 "갈리지 않는다"고 정정했다가, 짝지은 부트스트랩에서 다시 "갈린다"가 됐다. **처음 주장은 근거가 부실했고, 두 번째 정정은 검정력이 낮은 검정을 쓴 탓이다.** 지금 것이 가장 단단하다 — 표본이 20배 크고, 같은 시드를 짝지어 비교했고, checker가 독립 시드·독립 구현으로 재현했다.

**3. ④ DQN은 중앙값이 가장 높지만 ②와 갈리지 않는다** (+11.5, CI [−11.0, +35.0]). 분포가 이봉에 가깝다 — 크리틱이 맞으면 길게 가고 틀리면 즉사한다. argmax 정책이 크리틱에 100% 종속이라 회복 수단이 없다. **"④가 최고다"라고 말할 수 없다.**

**4. n=10 표와 순서가 다르다.** n=10에서는 ③(71.5) > ②(69.0)였는데 n=200에서는 ②(90.0) > ③(65.0)로 뒤집힌다. checker가 더 선명하게 보였다 — n=12에서 ②−③의 **점추정은 +28.5로 거의 정확했는데 CI가 [−18.0, +71.5]로 0을 품었고 4방향 순위는 통째로 틀렸다.** **작은 n에서 틀리는 것은 점추정이 아니라 순서와 확신이다.**

**그래서 이 표를 읽는 규칙**: `n ≥ 50`이고 짝지은 CI가 0을 안 품을 때만 순위를 말한다. 그 외에는 **격차만** 말한다. 크리틱 4종(66~106줄)과 크리틱 없는 3종(1,998줄)의 **두 자릿수 격차는 어떤 표본 크기로도 안 뒤집힌다.** 그것이 이 표가 확실하게 말하는 것이다.

## 1-ply 탐색은 이 가치함수로는 손해다 (규칙을 고쳐도)

`search_1ply` 의 평가 규칙이 틀렸던 것을 checker 가 실측으로 잡았고, 고쳤다.

```
구:  score(p₁) = v(p₁ 이후) + max_p₂ v(p₁→p₂ 이후)     ← 폐기
신:  score(p₁) =              max_p₂ v(p₁→p₂ 이후)     ← 말단 평가
```
합산은 **깊이가 다른 두 국면의 가치를 더해 중간 노드를 두 번 세고**, `landing_height`·`eroded_piece_cells` 를 서로 다른 두 배치에 대해 더한다 — 각각 자기 수의 속성이라 더하는 의미가 없다. 규칙 수정 자체는 옳다.

**그런데 고쳐도 결론이 안 바뀐다.** checker 가 쓴 시드 3개, 900수, 엔진 구동:

| | 시드별 점수 | 정규화 점수/조각 |
|---|---|---:|
| CEM 그리디 (탐색 없음) | 818,400 / 799,300 / 833,850 | **49.33** |
| 1-ply 말단 (수정본) | 778,450 / 767,750 / 779,650 | 46.56 |
| 1-ply 합산 (구 규칙) | 787,500 / 784,700 / 791,800 | 47.50 |

**세 시드 전부에서 두 탐색 변형 모두 그리디보다 낮다.** 그리고 **수정본이 구 규칙보다도 약간 낮다.** 즉 규칙 오류는 실재했지만 **적자의 원인은 아니었다.**

### 알려진 교란 요인을 제거해 봤다 — 도움은 되지만 격차는 안 닫힌다

`w` 는 CEM 이 **1스텝 그리디 평가용으로** 맞춘 것이다. 2-ply 탐색은 **다른 정책**이고, 같은 `w` 가 그 정책에 최적일 이유가 없다. 이건 우리가 **아는** 교란 요인이므로, 그것을 남긴 채 "탐색은 이득이 아니다"라고 결론 내릴 수는 없다. 그래서 **탐색을 롤아웃 안에 넣은 채 CEM 을 다시 학습**했다(`cem_search.json`, `cem.py --search`). 이제 CEM 이 **탐색 정책의** 가치함수를 찾는다.

같은 시드 10개, 상한 3,000, 엔진 구동, 레벨 보정 조각당 점수:

| | 정규화 점수/조각 |
|---|---:|
| CEM 그리디 (탐색 없음) | **48.8** |
| CEM 탐색-속-학습 → 탐색으로 플레이 | 46.8 |
| 1-ply 탐색 (그리디용 가중치) | 46.7 |

**교란을 제거해도 46.7 → 46.8 이다. 사실상 차이가 없다.**

(중간 기록: 이 값이 한때 47.3 이었다. 그때는 가중치를 `best_single_candidate` 로 골랐는데, 세대마다 평가 시드가 바뀌므로 그 선택법은 **운 좋은 세대의 가중치를 뽑을 수 있다.** 다른 CEM 산출물과 같이 `distribution_mean` 으로 통일하자 46.8 이 됐다. **선택법을 안전하게 바꾸자 개선이 사라졌다** — 그 0.5 는 학습 효과가 아니라 선택 잡음이었다는 뜻이다.)

**그래서 "가치함수가 그리디용이라 탐색이 손해였다"는 가설은 지지되지 않는다.** 교란을 제거해도 탐색 없는 48.8 에 못 미친다.

**정직한 단서 하나**: 이 비교는 학습 예산이 대등하지 않다. 탐색 롤아웃은 배치당 약 25배 비싸서, 같은 14분 안에 조각 상한을 (100, 200, 400, 800) 로 낮춰야 했다 — 그리디 학습의 (200, 500, 1500, 5000) 에 비해 훨씬 짧은 게임만 본다. **더 큰 예산을 주면 뒤집힐 여지가 있다.** 그래서 "탐색은 이 문제에서 원리적으로 무익하다"가 아니라 **"이 예산에서는 탐색이 값을 못 했다"**가 정확한 서술이다.

> 그리고 그 비용 자체가 결론의 일부다. **탐색이 정책 개선을 하려면 그 탐색을 학습 루프 안에 넣어야 하고, 그 순간 25배 비싸진다.** AlphaZero 가 자기대국에 막대한 계산을 쓰는 이유가 이것이다. 공부계획 4주차의 "매 결정마다 탐색을 돌릴 계산 여유가 있나"는 추론 시점만의 질문이 아니라 **학습 시점의 질문**이기도 하다.

> **줄 수로는 이 셋을 판정할 수 없다.** 셋 다 상한에 붙는다(1998.0 / 1998.0 / 1998.0). 점수 축에서만 갈린다 — 포화 지표로 순위를 매기면 "차이가 없다"는 잘못된 결론이 나오는 사례다.

**공부계획 4주차에 대한 정직한 교보재**: 탐색이 정책 개선을 한다는 AlphaZero 의 주장은 **가치함수가 그 탐색 깊이에 맞게 학습됐을 때** 성립한다. 평가자와 탐색 깊이가 어긋나면 탐색은 손해다. 구 규칙은 `search_1ply_sum.json` 으로 보존했다.

| 죽지 않는다 (10/10 상한 도달) | 1/10 | **미달** |
| tetris율 ≥ 30% | 13.4% | **미달** |
| 조각당 점수 `cem_linear` 대비 2배 | 1.19배 | **미달** |

**이 예산에서 점수 목표 학습은 실패했다.** 결과를 보고 기준을 정하면 무엇을 해도 성공이 되므로, 합격선은 학습 전에 고정했고 통과할 때까지 지표를 바꾸지 않았다.

**그리고 아래는 합격 여부와 무관하게 실제로 관측된 것이다. 둘 다 참이다.**

3번과 9번은 **완전히 같은 CEM, 같은 특징 8개, 같은 학습 예산**이다. 적합도 하나만 바꿨다.

| | 3번 (줄 목표) | 9번 (점수 목표) |
|---|---:|---:|
| tetris율 | 0.0% | **13.4%** |
| 정규화 점수 | 49.0 | **58.2** |
| 평균 줄 | 1,997.4 | 1,324.2 |
| 상한 도달(안 죽음) | 10/10 | 1/10 |

**목표를 바꾸자 성향이 뒤집혔다.** 3번은 영원히 한 줄씩 깎으며 절대 안 죽는다. 9번은 우물을 열어두고 I 조각을 기다렸다가 **한 번에 4줄을 터뜨린다.** 대신 기다리는 동안 높이가 올라가 **10판 중 9판은 죽는다.** 사용자가 요구한 "한 번씩 터뜨릴 때 팍 터뜨리는 게 고점"이 이것이다.

**학습된 가중치를 보면 그 성향이 그대로 보인다:**

| 특징 | 줄 목표 | 점수 목표 | |
|---|---:|---:|---|
| `bumpiness` | −0.139 | **+0.217** | ★ **부호가 뒤집혔다** |
| `cumulative_wells` | −0.181 | **−0.059** | 우물 페널티가 1/3로 |
| `holes` | −0.065 | −0.598 | 구멍은 훨씬 더 싫어함 |
| `column_transitions` | −0.810 | −0.479 | |

`bumpiness`가 양수라는 건 **표면이 울퉁불퉁한 것을 선호한다**는 뜻이다 — 즉 한 열을 일부러 비워 둔다. 우물 페널티도 3분의 1로 줄었다. **테트리스를 노리려면 우물을 열어둔 채 버텨야 한다는 것을, 아무도 안 가르쳤는데 가중치가 스스로 그렇게 배치됐다.** 반대로 구멍(`holes`) 페널티는 9배로 커졌는데, 우물을 파되 그 우물이 막히면 안 되기 때문이다.

### 왜 합격선을 못 넘었나

세 가지가 겹쳤고, 두 번째가 결정적이다.

1. **표현력** — Dellacherie 8종에 "우물을 의도적으로 관리한다"를 담을 항이 없다. `cumulative_wells`는 우물의 **비용**을 재지 그것을 **자산으로 유지하는 것**을 표현하지 못한다. 선형 정책이 표현할 수 없는 전략은 CEM이 아무리 돌아도 못 찾는다.
2. **탐색 분포가 3분 만에 죽었다** — 아래 절 참조. 60분을 줘도 실제로 탐색한 것은 앞의 168세대뿐이었다.
3. **지연 보상** — 우물 유지 비용은 즉시, 회수는 나중이다. 선형 afterstate 평가는 그 시차를 담을 구조가 아니다.

3번이 사실이라면 그것이 이 프로젝트에서 가장 값진 결론이다. **크레딧 할당 구간이 길어지는 문제에서 부트스트랩 크리틱이 왜 필요한가** — 사용자 공부계획의 축 그대로다.

### ★ CEM 탐색 분포가 3분 만에 붕괴했다 (그리고 로그에 찍히고 있었다)

60분 예산으로 돌린 점수 목표 학습의 곡선이다.

```
gen   elite   sigma_norm     경과
 60   60.64   0.039920        51s
100   60.11   0.000266       102s
140   59.67   0.000004       153s
168      —    0.000000       ← 분포 붕괴
340   62.53   0.000000       406s
```

`sigma`가 0이면 샘플링 분포가 **한 점**이다. 후보 64개가 전부 같은 가중치이므로 elite 선택에 고를 것이 없고 **학습이 원리적으로 불가능하다.** 그 뒤 197세대 동안 elite 점수가 57~64를 오간 것은 개선이 아니라 **매 세대 시드가 바뀌는 평가 노이즈**다.

원인은 내 CEM에 **분산 하한이 없었다는 것**이다. Szita-Lőrincz의 가산 노이즈 `Z_t`는 설계상 0으로 감쇠하므로 말기에 탐색을 살려주지 못한다. `sigma = max(sigma, sigma_min)`을 넣었고(`--sigma-min`, 기본 0.02), `sigma_norm < 1e-6`이면 **stdout에 붕괴를 명시**하고 종료 시 "몇 세대에서 죽었는가"를 요약한다.

**이건 15분과 60분 결과가 같았던 이유이기도 하다.** 예산을 늘려도 3분 뒤로는 아무 일도 일어나지 않았다.

> 그리고 **`sigma_norm`은 처음부터 곡선에 찍히고 있었다.** 값이 로그에 있었는데 아무도 그 열을 읽지 않았다. 이 프로젝트에서 반복된 형태 — 결함이 조용히 그럴듯한 결과 행세를 한다 — 의 한 사례다.

### 점수 목표에서 밟은 함정 (기록으로 남긴다)

처음엔 적합도를 **조각당 원시 점수**로 잡았다. 결과는 **조각당 1,546점인데 tetris율 0.1%** — 오래 살면서 싱글만 긁는 정책이 나왔다. 원인은 level 배수다. `level = 1 + 줄수/10`이 게임 내내 오르므로 **level 60에서의 싱글이 6,000점, level 1에서의 테트리스가 800점**이 된다. 즉 적합도가 "얼마나 오래 살았나"를 다시 재고 있었고, 포화를 피하려고 바꾼 목표가 포화된 목표로 되돌아가 있었다.

**level로 나누자 한 번에 풀렸다** (tetris율 0.1% → 13.0%). 지표를 설계할 때 "무엇을 재는가"보다 **"이 지표가 몰래 무엇을 다시 재는가"**를 봐야 한다는 사례다.

### 이 표에서 실제로 읽을 수 있는 것

1. **크리틱 기반 4종(④~⑦)이 크리틱 없는 대조군(②③⑧⑨)에 20~30배 진다.** 이것이 이 프로젝트의 중심 결과다. 정직하게 읽으면 이렇다 — **정책이 숫자 8개뿐이고 롤아웃이 싸면, 공부계획이 다루는 크레딧 할당 기계장치는 값을 못 한다.** 크리틱은 정책이 크고 표본이 비쌀 때 값을 한다. 여기는 둘 다 아니다. 공부계획 "밥약 전 자기 점검" 2번·4번의 실물 답이다.

2. **①②③④의 비교는 시드 10개로 하면 안 된다.** 아래 별도 절에 시드 **200개** 재평가를 실었다. n=10에서 보이던 순서가 n=200에서 바뀐다.

3. **⑦ DQN은 꼬리가 극단적으로 두껍다.** n=200에서 중앙값 101.5인데 평균은 172.5다(1.7배). 한 판의 운이 평균을 끌어올린다. argmax 정책이 크리틱에 100% 종속이라, 크리틱이 맞은 국면에서는 길게 가고 어긋나면 즉시 무너진다.

5. **⑧ 1-ply 탐색은 CEM보다 못하다.** 줄 수로는 둘 다 상한에 붙어 구분이 안 되지만 점수 축에서는 확실히 진다(46.56 대 49.33). 별도 절 참조.

6. **②(사람이 손으로 정한 가중치)가 ③(학습한 가중치)과 사실상 같다.** 학습이 사람을 못 이겼다 — 정확히는, 둘 다 천장에 닿아서 이길 여지가 없었다.

### 마지막에 잡은 결함 — argmax 동점 (기록)

평가 하네스 둘(engine 기반 `evaluate.py`, fastsim 기반 학습 내 점검)이 **같은 가중치·같은 시드로 44% 다른 줄 수**를 냈다. 원인은 규칙이 아니라 **부동소수점 동점**이었다.

`cem_score` 시드 900003 1327수 실측:
```
placement  7 → -23.665216819989176
placement 16 → -23.665216819989173      1e15분의 3 차이
```
numpy의 2차원 `X @ w`(BLAS)와 스칼라 루프가 **다른 인덱스를 골랐고**, 두 배치는 다른 수이므로 그 뒤로 게임이 통째로 갈라졌다. 한쪽은 1,996줄, 다른 쪽은 800줄. 둘 다 "맞았다".

**처방**: `features.argmax_stable()`. 두 값의 차이가 `1e-9` 이하면 같은 것으로 보고 **첫 번째**를 고른다.
```
best = 0;  for i:  if scores[i] > scores[best] + 1e-9:  best = i
```
`>`·`+`·리터럴 상수뿐이라 **두 언어가 구조적으로 같은 분기를 탄다.** `legal_placements`가 (rot, x) 순 정렬이므로 첫 최댓값 = 가장 낮은 (rot, x)다. 적용 후 두 하네스가 **시드별로 완전히 일치**한다.

**처음에는 "9자리로 반올림한 뒤 비교"로 만들었고, 그것을 다시 고쳤다.** 파이썬 `round()`는 동점을 짝수로, JS `Math.round()`는 +∞ 쪽으로 보낸다 — **점수가 전부 음수라 두 규칙이 반대로 간다.** 반올림은 애초에 필요가 없었다(하려던 일은 "1e-9 미만 차이를 동점으로 보기"였고 epsilon이 그걸 직접 한다). 지금은 반올림 단계 자체가 없다.

**왜 늦게 잡혔나**: 패리티 테스트가 **무작위 배치**로 돌고 있었다. 무작위는 23수에 죽어 보드가 낮게 유지되는데, **동점은 보드가 높고 복잡해져야 생긴다.** 그래서 패리티는 계속 PASS인데 실제 숫자는 어긋나 있었다. 지금은 학습된 가중치로 양쪽을 몰아 13,000수까지 돌린다(`--policy cem`). **검증 하네스는 검증 대상이 실제로 사는 상태를 방문해야 한다.**

### 혼동하지 말 것 — 갈림이 두 건이었고 원인이 다르다

| | 증상 | 원인 |
|---|---|---|
| **파이썬 하네스 둘** | 같은 가중치·시드로 1,996줄 대 800줄 | **동점 처리.** numpy BLAS 내적과 스칼라 루프가 마지막 비트에서 갈렸다. 위 규칙이 고쳤다 |
| **파이썬 대 JS** | 10시드 중 3개가 종반에 +1·+1·+10줄 | **동점이 아니었다.** web이 `scoreAll`에 넣어 둔 **문서에 없는 죽음 페널티(−1e6)**였다. 제거하니 10/10 일치 |

두 번째 건에서 반올림 규칙 차이가 유력한 용의자로 지목됐지만 **web이 실게임 점수 42,594개를 대조해 불일치 0건으로 기각했다** — 정확히 절반인 값은 합성 데이터에만 나오고 실제 점수 분포에는 없다. **반올림 규칙 차이는 별개로 존재하던 잠재 위험이었고, 원인이 아니라는 것이 밝혀진 뒤에도 제거는 유지했다**(구조적으로 없애는 편이 낫고, 파이썬 수치가 하나도 안 변하는 것을 확인했다).

**타이 규칙이 실제로 일하고 있다는 증거**: web이 종반 특징벡터 6,930개를 numpy BLAS와 JS 스칼라 루프로 각각 채점했더니 **원시 내적값의 34.1%가 마지막 비트에서 달랐고, 타이 규칙 적용 후에는 0%였다.** 타이 규칙이 없으면 이 프로젝트는 언어 간 재현이 불가능하다.

### 알려진 한계 (숨기지 않는다)

- **advantage 정규화를 일부러 넣지 않았다.** 흔한 안정화 기법이지만 넣으면 **순수 REINFORCE에 몰래 baseline이 들어가** ①과 ②의 비교가 무너진다. 그래서 ①은 이론이 말하는 만큼 불안정하다. 그게 맞는 그림이다.
- **PG/DQN은 각 10분 벽시계 상한 안의 결과다.** 더 돌리면 나아진다. 그러나 CEM을 따라잡는 것이 목적이 아니다.
- **CEM이 찾은 `eroded_piece_cells` 가중치의 부호가 음수다.** 줄 지우기를 보상하는 특징인데 상식과 반대다. 그런데도 조각당 0.4줄, 즉 **이론 최대율**로 지운다(조각 4칸 ÷ 한 줄 10칸). 높이·구멍·기둥전이를 극단적으로 억제하면 줄 삭제가 **목표가 아니라 부산물로** 따라오기 때문이다. 사람이 설계한 해와 다른 해를 찾은 사례다.
- **위 표의 숫자는 `fastsim`이 아니라 `engine`에서 나왔다.** 학습 롤아웃만 `fastsim`을 쓴다. 리드 판정 — 사용자에게 도달하는 수치는 엔진에서만 나온다. 이렇게 하면 `fastsim`이 갈라져도 평가 단계에서 성능 하락으로 드러난다.
- **패리티**: `parity_fastsim.py`가 학습된 정책으로 양쪽을 몰아 매 배치마다 보드 전체·조각 순서·합법 배치 수·기하·`lines_cleared`·`landing_height`·`eroded_piece_cells`·게임오버 시점을 대조한다. 이 대조가 결함 3건(스폰 버퍼 2행 누락, 게임오버 판정 규칙 상이, argmax 동점)을 잡아냈고 위 표는 전부 수정 후의 결과다. `weights/*.json`의 `meta.parity_verified`는 `artifacts.py`가 이 테스트를 실제로 실행하고 종료코드로 찍는다.
- **9번은 10판 중 9판 죽는다.** 우물을 열어두고 버티는 대가다. 줄 수로는 3번에 지고, 정규화 점수와 tetris율로는 이긴다. **어느 쪽이 "더 나은 정책"인지는 목표를 정해야 답이 나온다** — 그게 이 두 패널을 나란히 두는 이유다.

## 재현

### `--minutes` 는 목표가 아니라 상한이다 (함정)

`--minutes 60` 으로 띄운 학습이 **6분 만에 끝났다.** `--generations` 기본값이 먼저 소진됐기 때문이다. 둘 중 **먼저 오는 쪽**에서 멈춘다.
→ 기본값을 사실상 무제한(100000)으로 바꿔 `--minutes` 가 실제 예산이 되게 했다. 생성 수로 끊고 싶을 때만 `--generations` 를 줘라.

또 하나: **`--resume` 을 안 줘도 체크포인트가 있으면 이어받는다.** 처음부터 다시 돌리려면 `weights/ckpt_cem_<objective>.json` 을 지워야 한다. 이걸 모르면 "60분 돌렸다"고 믿는 결과가 사실은 이전 실행의 재현일 수 있다.

```bash
cd rl

# 검증 (전부 PASS 여야 한다)
python3 features.py          # 특징 정의 자체검증 + web용 패리티 픽스처
python3 fastsim.py           # 시뮬레이터 자체검증 + 속도 측정
python3 nn.py                # 역전파를 유한차분으로 검증
python3 parity_fastsim.py    # ★ fastsim 이 engine 과 같은 게임인지 대조

# 학습 (--resume 은 CEM 만 지원한다)
python3 cem.py --objective lines --minutes 15 --candidates 64 --seeds 8 --workers 100
python3 cem.py --objective score --minutes 15 --candidates 64 --seeds 8 --workers 100
python3 cem.py --objective score --features wells10 --minutes 55 --candidates 64 --seeds 8 --workers 50
#   --features 는 이름 붙은 특징 집합이다. dellacherie8(고정 기본) / wells10(+max_well_depth, well_count).
#   새 집합은 새 파일로 나가고 기존 8특징 파일은 건드리지 않는다. 소비자는 파일의
#   `features` 목록 순서대로 값을 뽑아야 한다 — 인덱스로 읽으면 집합이 늘 때 조용히 깨진다.
#   --minutes 는 상한이다. --generations 기본값(무제한)과 함께 쓰면 시간이 실제 예산이 된다.
#   체크포인트가 있으면 --resume 없이도 이어받는다. 처음부터 돌리려면 ckpt 를 지워라.
#   --sigma-min 0.02 가 탐색 분포 붕괴를 막는다. 0 으로 두면 3분 만에 죽는다.
python3 pg.py  --mode reinforce           --time-budget 600 --workers 24
python3 pg.py  --mode reinforce_baseline  --time-budget 600 --workers 24
python3 pg.py  --mode a2c                 --time-budget 600 --workers 24
python3 dqn.py                            --time-budget 600 --workers 24
python3 search.py                         # cem_linear.json 재사용, 학습 없음

# 마무리 — 이 순서를 지켜야 한다
python3 evaluate.py --cap 5000            # engine 기반 비교표
python3 artifacts.py --parity run         # parity 스탬프 + index.json + bundle
```
마지막 `artifacts.py` 를 빠뜨리면 `weights/index.json` 과 `weights_bundle.js` 가 낡은 채로 남고, web 이 그 둘을 읽는다.

## 공부계획 대응표

| 패널 | 전략 | 크리틱이 추정 | 부트스트랩 | on/off | 공부계획 |
|---|---|---|---|---|---|
| 1 | Random | 없음 | — | — | 대조군 |
| 2 | Dellacherie 수동 | 없음 | — | — | 대조군 |
| 3 | CEM 선형 | 없음 | — | — | 축 밖 |
| 4 | REINFORCE | 없음 | — | on | ① |
| 5 | REINFORCE + baseline | v (기준선) | **아니오** | on | ② |
| 6 | A2C (1-step) | v | **예** | on | ③ |
| 7 | DQN (afterstate) | q | 예 | **off** | ④ |
| 8 | 1-ply 탐색 | v (말단 평가만) | — | — | 4주차 AlphaZero |
| 9 | CEM 선형 (점수 목표) | 없음 | — | — | 축 밖 · 목표 대조군 |
