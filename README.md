# tetris-rl-testbed

**브라우저에서 바로 실행 →** https://revinqbank.github.io/tetris-rl-testbed/

테트리스를 강화학습 실험대로 쓴 기록이다. 사람이 직접 플레이할 수 있고,
학습된 정책 14개가 **같은 조각 순서로 동시에** 판을 두는 것을 나란히 볼 수 있다.
서버가 필요 없다 — 정책 계산과 가중치가 전부 페이지 안에 들어 있다.

## 이 실험이 알아낸 것

> **성능을 바꾼 것은 알고리즘이 아니라 문제 정의였다.**

같은 게임 위에서 진화탐색(CEM), REINFORCE, REINFORCE+baseline, A2C, DQN,
1수 앞 탐색을 돌렸다. 최종 순위는 이렇다 — **정규화 점수/조각**, 같은 시드 10판,
조각 상한 3,000.

| 정규화 점수/조각 | 전략 |
|---:|---|
| **82.2** | CEM · 점수 목표 · 우물 특징 |
| 74.2 | CEM · 점수+생존 목표 |
| 50.4 | 델라체리 (사람이 손으로 정한 가중치, **학습 없음**) |
| 49.0 | CEM · 선형 |
| 46.8 | 1수 앞 탐색 |
| 44.2 | DQN |
| 41.1 | REINFORCE + baseline |
| 40.0 | REINFORCE |
| 38.5 | A2C |
| 0.0 | 무작위 |

**신경망 넷이 전부 아래에 있고, 학습을 하지 않은 사람 손 가중치가 그 넷을 다 이긴다.**

그런데 이것을 *"단순한 방법이 이겼다"* 로 읽으면 틀린다. 실제로 성능을 움직인 것은
방법 교체가 아니라 **문제를 어떻게 정의했는가**였다.

| 무엇을 바꿨나 | 결과 |
|---|---|
| 행동공간을 프레임 단위 키 입력 → **배치**(회전 × 열) 열거로 | 애초에 학습이 가능해졌다 |
| 목적함수를 지운 줄 수 → 점수 → **점수 × 생존**으로 | 4줄 동시 삭제 0% → 59%, 생존 15배 |
| 특징 8개 → **10개** (우물 관련 2종 추가) | 못 찾던 전략을 찾았다 |
| **알고리즘을 하나 더 얹음** (1수 앞 탐색) | **이득 없음** |

마지막 줄이 요점이다. 문제 정의를 바꾼 것은 전부 효과가 있었고,
알고리즘을 더한 것만 효과가 없었다.

CEM이 이긴 이유도 단순해서가 아니다. 좋은 특징 10개가 이미 있으니 **찾을 것이
파라미터 10개뿐**이었고, 신경망은 그 특징이 표현하는 것을 처음부터 다시 배워야 해서
표본 효율이 훨씬 나빴다. **특징을 사람이 잘 만들어 두면 학습기는 단순해도 된다** —
이 실험대가 보여주는 것은 그것이다.

**공정하게 덧붙이면**, 신경망 넷은 CEM만큼 튜닝을 받지 않았다.
*"딥RL이 원래 약하다"* 가 아니라 *"이 조건에서 이 예산으로는 졌다"* 이다.
검증하지 못한 것들은 [docs/WALKTHROUGH.md](docs/WALKTHROUGH.md) §11에 모아 두었다.

## 화면 셋

| | |
|---|---|
| **PLAY** | 직접 플레이. 이동/회전/소프트드롭/하드드롭/홀드, 락 딜레이 500 ms, 난이도 3단계 |
| **ARENA** | 정책 14개가 같은 조각 순서로 동시에 플레이. 순위는 중앙값으로 매긴다 |
| **LEARN** | 각 정책이 무엇을 어떻게 학습하는지 — 크리틱의 역할과 갱신식 |

난이도는 속도가 아니라 **정보량**으로 조절한다: 노멀은 다음 조각 5개 + 홀드,
하드는 1개, 익스트림은 미리보기 없음. 속도를 올리면 사람만 불리하고
에이전트는 아무 영향이 없기 때문이다.

## 직접 돌려보기

```bash
bash tools/serve.sh                  # 웹 앱 (기본 8080)
python3 engine/parity.py             # 규칙 검증 + Python↔JS 대조 (210 케이스)
bash tests/run_all.sh                # 테스트 15종
python3 rl/evaluate.py --cap 50000   # 전략 비교표 재생성
python3 rl/cem.py --objective score_safe --features wells10 --minutes 55
```

학습에는 `numpy`가, 신경망 계열(REINFORCE/A2C/DQN) 재학습에는 `torch`가 필요하다.
없으면 해당 테스트는 **fail이 아니라 skip**으로 표시된다.
`TETRIS_PY` 환경변수로 그 인터프리터를 지정할 수 있다.

## 구조

| 폴더 | 무엇 |
|---|---|
| `engine/` | 규칙의 정본(Python). SRS 회전·킥, 점수, 락 딜레이. `parity.py`가 JS 구현과 대조 |
| `web/` | 브라우저 앱. `engine.js`가 규칙, `policies.js`가 정책, `arena.js`가 다중 패널 |
| `rl/` | 학습·평가. `cem.py`(진화탐색), `pg.py`(REINFORCE/A2C), `dqn.py`, `evaluate.py` |
| `weights/` | 학습된 가중치와 평가 결과. `index.json`이 웹이 읽는 목록 |
| `tests/` | 15종. 규칙·점수·병렬구현 일치·UI를 실제 브라우저로 검사 |
| `docs/` | 아래 참조 |
| `logs/` | 실제 학습 로그 (세대별 적합도 곡선 포함) |

**규칙 구현이 넷이다** — `engine/engine.py`, `web/engine.js`, `rl/fastsim.py`(학습용
고속 시뮬레이터), `web/engine.classic.js`. 넷이 갈라지면 결과가 조용히 틀어지므로
서로 대조하는 테스트로 묶어 두었다.

## 이 저장소에 없는 것

작업용 내부 문서 두 개(설계 계약 `PROJECT.md`, 세션 인수인계 `HANDOFF.md`)는 뺐다.
코드 주석에 *"PROJECT.md가 요구한 것"* 같은 언급이 남아 있는데, 그것은 합격 기준과
담당 범위를 적어 둔 내부 문서를 가리킨다. 그 기준 자체는 WALKTHROUGH §11에 결과와
함께 옮겨 두었으므로 읽는 데 빠지는 것은 없다.
